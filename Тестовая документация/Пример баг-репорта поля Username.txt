[Registration] Поле «Логин» (username) помечено как необязательное и не блокирует отправку формы, хотя по требованиям является обязательным
Метаданные
Параметр	Значение
ID	BUG-1042
Проект	Приложение (форма регистрации)
Компонент	Registration Form / Frontend validation
Версия сборки	1.4.2 (build 2026-11-18)
Окружение	Chrome 131, Windows 11, staging
Severity	Major

Статус	New
Автор	QA

Предусловия

    Открыта страница регистрации.

    Пользователь не авторизован.

    В системе нет аккаунта с тестовыми данными из шагов воспроизведения.

Шаги воспроизведения

    Открыть форму регистрации.

    Заполнить обязательные поля: email, пароль, имя — валидными значениями.

    Поле «Логин» (username) оставить пустым.

    Нажать кнопку «Зарегистрироваться».

Фактический результат

    Поле «Логин» отображается без индикатора обязательности (нет звездочки/пометки «обязательно»).

    Форма успешно отправляется, аккаунт создается без логина (либо логин генерируется автоматически, либо сохраняется пустым значением — в зависимости от поведения бэкенда).

    Ошибка валидации не появляется.

Ожидаемый результат

    Поле «Логин» помечено как обязательное (звездочка/подпись «обязательно», aria-required="true").

    При пустом поле форма не отправляется, под полем появляется сообщение об ошибке: «Поле обязательно для заполнения».

    Фокус переводится на поле «Логин» (или на первое невалидное поле).

    Запрос на создание аккаунта на сервер не уходит.

Дополнительно (по результатам исследования)

    В требованиях (FR-12, п. 3.1) логин указан как обязательное поле.

    Атрибут required у input отсутствует в DOM; в конфигурации формы поле помечено optional: true — вероятная причина: неверная конфигурация схемы валидации.

    Проверено на Firefox 133 и Safari 18 — воспроизводится стабильно (кроссбраузерно).
