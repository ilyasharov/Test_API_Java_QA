1. Добавление товара в корзину

Актор: Пользователь (гость или авторизованный)
Цель: Положить выбранный товар в корзину для последующей покупки
Предусловия: Пользователь находится на странице товара (карточка товара)

Основной поток:

    Пользователь открывает карточку товара.

    Выбирает доступные характеристики (размер, цвет и т.п.), если применимо.

    Нажимает кнопку «Купить».

    Система добавляет товар в корзину и показывает подтверждение (тост/уведомление, обновление счётчика корзины).

    Пользователь может продолжить покупки или перейти в корзину.

Альтернативные потоки / исключения:

    Товар закончился — кнопка неактивна, отображается «Нет в наличии» / «Сообщить о поступлении».

    Не выбраны обязательные характеристики — система подсвечивает поля и просит выбрать размер/цвет.

    Товар уже в корзине — система либо увеличивает количество, либо предупреждает «Товар уже в корзине».

    Гость — корзина хранится локально (localStorage/сессия); при входе — предложение объединить корзины.

    Ошибка сети — сообщение об ошибке и повтор действия.

Результат: Товар в корзине, счётчик обновлён, пользователь получил обратную связь.
UX/разработка: микроанимация добавления, ненавязчивый тост, быстрый переход в корзину, сохранение корзины между сессиями.
2. Изменение характеристик товара в корзине

Актор: Пользователь
Цель: Изменить размер (или другой атрибут) уже добавленного товара — например, носков
Предусловия: Товар находится в корзине, у товара есть вариативность (размеры)

Основной поток:

    Пользователь открывает корзину.

    У товара выбирает новый размер из выпадающего списка / селектора.

    Система проверяет наличие выбранного размера.

    Система обновляет позицию в корзине (цена, наличие, изображение) и пересчитывает итог.

Альтернативные потоки / исключения:

    Выбранного размера нет в наличии — опция неактивна или показывается предупреждение, изменение не применяется.

    Изменение влияет на акцию — если скидка зависела от размера/варианта, система пересчитывает скидку и уведомляет пользователя.

    Цена изменилась — показывается новое значение и, при необходимости, уведомление.

    Товар с индивидуальными параметрами (гравировка) — изменение может требовать повторного подтверждения.

Результат: Позиция в корзине обновлена с новыми характеристиками, итог пересчитан.
UX/разработка: изменение «на месте» без перезагрузки, явная обратная связь, защита от случайных изменений, синхронизация с остатками на складе.
3. Изменение количества товара в корзине

Актор: Пользователь
Цель: Увеличить или уменьшить количество единиц товара
Предусловия: Товар в корзине

Основной поток:

    Пользователь открывает корзину.

    Нажимает «+» / «−» или вводит количество вручную.

    Система проверяет доступный остаток.

    Система обновляет количество и пересчитывает сумму (с учётом скидок и доставки).

Альтернативные потоки / исключения:

    Превышен остаток на складе — количество ограничивается максимумом, показывается сообщение.

    Уменьшение до 0 — система предлагает удалить товар (или удаляет с возможностью отмены).

    Минимальный заказ / кратность — например, товар продаётся упаковками по 2 шт.; система округляет или блокирует недопустимое значение.

    Порог бесплатной доставки — при изменении количества система показывает, сколько осталось до бесплатной доставки.

    Промокод перестал применяться — уведомление о пересчёте скидки.

Результат: Количество и сумма обновлены, остатки проверены.
UX/разработка: мгновенный пересчёт, дебаунс запросов к серверу, защита от ввода отрицательных/дробных значений, понятные сообщения об ограничениях.
4. Оформление заказа

Актор: Пользователь
Цель: Заполнить форму заказа, выбрать доставку и оплатить товар
Предусловия: В корзине есть товары, пользователь нажал «Оформить заказ»

Основной поток:

    Пользователь переходит к оформлению.

    Заполняет контактные данные (или выбирает из сохранённых).

    Выбирает способ доставки (курьер, пункт выдачи, самовывоз) и адрес.

    Видит итоговую стоимость с учётом доставки и скидок.

    Выбирает способ оплаты (карта, СБП, электронный кошелёк, при получении).

    Подтверждает заказ и оплачивает.

    Система создаёт заказ и показывает подтверждение с номером заказа.

Альтернативные потоки / исключения:

    Не заполнены обязательные поля — валидация с подсветкой ошибок.

    Адрес вне зоны доставки — система предлагает альтернативу (самовывоз/другой ПВЗ).

    Оплата не прошла — сообщение об ошибке, возможность повторить или выбрать другой способ; заказ сохраняется как «неоплаченный».

    Товар закончился во время оформления — предупреждение и предложение убрать позицию.

    Гость — предложение зарегистрироваться или оформить как гость.

    Промокод — поле для ввода, проверка валидности и пересчёт.

    Таймаут сессии — сохранение черновика заказа.

Результат: Заказ создан, оплачен (или ожидает оплаты), пользователь получил подтверждение (на экране и на email).
UX/разработка: минимум шагов, автозаполнение, прозрачная итоговая сумма, понятные ошибки, защита от двойного списания, интеграция с платёжным шлюзом.
5. Возврат товара в корзину (отмена удаления)

Актор: Пользователь
Цель: Вернуть случайно удалённый товар обратно в корзину
Предусловия: Пользователь удалил товар из корзины

Основной поток (undo):

    Пользователь нажимает «Удалить» у позиции.

    Товар удаляется, появляется уведомление с кнопкой «Отменить» (в течение 5–10 секунд).

    Пользователь нажимает «Отменить».

    Товар возвращается в корзину на прежнее место с прежними параметрами и количеством.

Альтернативные потоки / исключения:

    Пользователь не нажал «Отменить» — товар окончательно удалён; можно вернуть через «Историю» / «Избранное» / повторный поиск.

    Товар закончился за это время — при возврате показывается предупреждение о недоступности.

    Сессия истекла / страница перезагружена — корзина восстанавливается из сохранённого состояния (если реализовано).

    Удаление всей корзины — аналогичный механизм отмены для массового действия.

Результат: Товар восстановлен в корзине.
UX/разработка: «snackbar» с undo, хранение удалённых позиций в течение короткого времени, отмена без перезагрузки страницы, доступ к ранее удалённым через историю.
6. Информация об акциях и скидках

Актор: Пользователь
Цель: Увидеть акции и скидки на выбранные товары и понять итоговую выгоду
Предусловия: В корзине есть товары, часть из которых участвует в акциях

Основной поток:

    Пользователь открывает корзину.

    Система отображает для каждой позиции: базовую цену, скидку, итоговую цену.

    Отображается блок «Ваша выгода» / «Скидка по акции».

    Пользователь видит, какие акции применены автоматически, а какие можно активировать (промокод, клубная цена).

    При изменении состава корзины скидки пересчитываются, и пользователь получает уведомление.

Альтернативные потоки / исключения:

    Условия акции не выполнены — например, «3 по цене 2», но в корзине 2 товара; система подсказывает, сколько добавить.

    Скидки не суммируются — система показывает, какая скидка применена и почему.

    Промокод недействителен — сообщение с причиной (истёк, не для этого товара, минимальная сумма).

    Скидка действует ограниченное время — таймер/предупреждение об окончании акции.

    Скидка на доставку — отображение порога бесплатной доставки и прогресс-бар.

Результат: Пользователь понимает, какие скидки применены, сколько он экономит и как получить дополнительную выгоду.
UX/разработка: прозрачное отображение цен (зачёркнутая старая + новая), блок «экономия», подсказки по акциям, корректный пересчёт при любых изменениях корзины, доступность (не только цветом).
